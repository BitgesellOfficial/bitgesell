# PR review checklist (quick pass)

This short checklist helps contributors send review-ready pull requests on the first pass.

## Before opening a PR

- Keep the change focused on one objective.
- Confirm the branch is rebased onto current `master`.
- Run the smallest relevant local checks for the changed area.
- Write a clear title with an area prefix (for example `doc:`, `test:`, `net:`).

## In the PR description

- Explain what changed and why.
- Link related issue(s) and prior discussion.
- Include a quick test/validation note.
- Mention known limitations or follow-up work, if any.

## Before requesting review

- Remove accidental formatting-only noise.
- Ensure links and file paths in docs are valid.
- Re-read from reviewer perspective: easy to scan, easy to verify.
- Reply to review comments with either a patch or a reasoned response.
